## 作用

代理模式为其他对象提供一种代理，以控制对这个对象的访问。在不修改目标对象代码的前提下，通过代理对象对目标对象的功能进行增强（如日志、事务、权限校验、耗时统计等通用性逻辑），是 AOP（面向切面编程）的底层实现基础。

## 遵循原则

- 遵循开闭原则，可以在不修改目标对象的情况下，通过代理类扩展新的功能
- 遵循单一职责原则，业务逻辑由目标对象负责，通用增强逻辑由代理对象负责，各司其职
- 遵循依赖倒转原则，客户端针对抽象主题接口编程，而不是具体实现类

## 定义

代理模式包含三种角色：

- 抽象主题角色（Subject）：定义目标对象和代理对象的公共接口，客户端通过该接口访问目标对象
- 真实主题角色（RealSubject）：真正执行业务逻辑的目标对象，是被代理的对象
- 代理角色（Proxy）：内部持有真实主题对象的引用，与真实主题实现相同的接口，在调用真实主题方法前后织入增强逻辑

根据代理类生成的时机不同，代理模式分为**静态代理**和**动态代理**两种。

## 静态代理模式

静态代理是指代理类在**编译期**就已经确定，由程序员手动编写（或通过工具生成）代理类的源代码，与目标类实现相同的接口。

### 示例代码

```java
// 抽象主题接口
public interface UserService {

    void saveUser();

}

// 真实主题类（被代理的目标对象）
public class UserServiceImpl implements UserService {

    @Override
    public void saveUser() {
        System.out.println("====保存用户信息====");
    }

}

// 代理类，与目标类实现相同的接口，内部持有目标对象的引用
public class UserServiceProxy implements UserService {

    private final UserService target;

    public UserServiceProxy(UserService target) {
        this.target = target;
    }

    @Override
    public void saveUser() {
        // 前置增强逻辑
        System.out.println("====开启事务====");
        target.saveUser();
        // 后置增强逻辑
        System.out.println("====提交事务====");
    }

}

// 客户端测试类
public class ProxyTest {

    public static void main(String[] args) {
        UserService userService = new UserServiceProxy(new UserServiceImpl());
        // 控制台输出：
        // ====开启事务====
        // ====保存用户信息====
        // ====提交事务====
        userService.saveUser();
    }

}
```

### 优缺点

- 优点：实现简单，易于理解；在不修改目标类的前提下完成功能增强，符合开闭原则
- 缺点：每一个目标类都需要手动编写一个代理类，目标类增多时代码量成倍膨胀，产生大量重复的代理类；接口新增方法时，目标类和所有代理类都要同步修改，维护成本高

## 动态代理模式

所谓动态代理就是在 JVM 运行时，通过字节码的方式动态生成代理类，并实例化代理对象。不需要像静态代理模式一样，硬编码代理类。

动态代理主要有两种实现方式：**JDK 动态代理**和 **CGLIB 动态代理**。

### JDK 动态代理

JDK 动态代理是 JDK 原生提供的实现，通过 `java.lang.reflect.Proxy.newProxyInstance()` 在运行时生成代理类，生成的代理类继承 `Proxy` 并实现目标接口。由于 Java 单继承的限制，**JDK 动态代理只能代理实现了接口的类**。

```java
// 抽象主题接口和真实主题类，与静态代理示例相同
public interface UserService {

    void saveUser();

}

public class UserServiceImpl implements UserService {

    @Override
    public void saveUser() {
        System.out.println("====保存用户信息====");
    }

}

// 增强逻辑处理器，实现 InvocationHandler 接口
public class LogInvocationHandler implements InvocationHandler {

    // 被代理的目标对象
    private final Object target;

    public LogInvocationHandler(Object target) {
        this.target = target;
    }

    @Override
    public Object invoke(Object proxy, Method method, Object[] args) throws Throwable {
        // 前置增强逻辑
        System.out.println("====方法 " + method.getName() + " 执行前打印日志====");
        Object result = method.invoke(target, args);
        // 后置增强逻辑
        System.out.println("====方法 " + method.getName() + " 执行后打印日志====");
        return result;
    }

}

// 客户端测试类
public class JdkProxyTest {

    public static void main(String[] args) {
        UserService target = new UserServiceImpl();
        // 运行时动态生成代理对象
        UserService proxy = (UserService) Proxy.newProxyInstance(
                target.getClass().getClassLoader(),
                target.getClass().getInterfaces(),
                new LogInvocationHandler(target));
        // 控制台输出：
        // ====方法 saveUser 执行前打印日志====
        // ====保存用户信息====
        // ====方法 saveUser 执行后打印日志====
        proxy.saveUser();
    }

}
```

核心原理：`Proxy.newProxyInstance()` 根据传入的接口列表，在运行时通过字节码技术生成一个 `$Proxy0` 代理类，该代理类的所有方法调用都会统一转发到 `InvocationHandler.invoke()` 中，因此一套增强逻辑可以复用于任意接口、任意方法，解决了静态代理代码膨胀的问题。

### CGLIB 动态代理

CGLIB（Code Generation Library）是一个基于 ASM 的字节码生成框架，它通过**继承目标类**的方式生成子类代理，并覆写目标方法织入增强逻辑，因此**可以代理没有实现接口的普通类**。由于采用继承方式，目标类不能是 `final` 类，目标方法也不能是 `final` 或 `private` 方法。

使用时需要引入 CGLIB 依赖（Spring 已内置，无需单独引入）：

```java
// 真实主题类，不需要实现任何接口
public class UserServiceImpl {

    public void saveUser() {
        System.out.println("====保存用户信息====");
    }

}

// 增强逻辑拦截器，实现 MethodInterceptor 接口
public class LogMethodInterceptor implements MethodInterceptor {

    @Override
    public Object intercept(Object obj, Method method, Object[] args, MethodProxy proxy) throws Throwable {
        // 前置增强逻辑
        System.out.println("====方法 " + method.getName() + " 执行前打印日志====");
        // 注意：使用 proxy.invokeSuper 调用父类（目标类）方法，
        // 不能使用 proxy.invoke，否则会递归调用代理类自身导致栈溢出
        Object result = proxy.invokeSuper(obj, args);
        // 后置增强逻辑
        System.out.println("====方法 " + method.getName() + " 执行后打印日志====");
        return result;
    }

}

// 客户端测试类
public class CglibProxyTest {

    public static void main(String[] args) {
        Enhancer enhancer = new Enhancer();
        // 设置父类，即被代理的目标类
        enhancer.setSuperclass(UserServiceImpl.class);
        // 设置方法拦截器
        enhancer.setCallback(new LogMethodInterceptor());
        // 运行时动态生成代理对象（目标类的子类）
        UserServiceImpl proxy = (UserServiceImpl) enhancer.create();
        proxy.saveUser();
    }

}
```

### JDK 动态代理与 CGLIB 动态代理对比

| 对比项 | JDK 动态代理 | CGLIB 动态代理 |
|---|---|---|
| 实现方式 | 实现目标接口，反射调用目标方法 | 继承目标类，生成子类覆写目标方法 |
| 代理要求 | 目标类必须实现接口 | 目标类无需实现接口，但不能是 final 类 |
| 依赖 | JDK 原生支持，无需额外依赖 | 需要引入 CGLIB 依赖（Spring 已内置） |
| 性能 | 反射调用，早期版本较慢，JDK 8 之后差距不大 | 通过 FastClass 索引直接调用，理论上略快 |
| Spring AOP 默认策略 | 目标类实现了接口时默认使用 | 目标类没有实现接口时使用 |

## 应用场景

- **Spring AOP**：事务管理（`@Transactional`）、日志切面、权限校验等，底层就是 JDK 动态代理和 CGLIB 动态代理的组合实现
- **MyBatis**：Mapper 接口没有实现类，`SqlSession.getMapper()` 返回的就是 JDK 动态代理生成的代理对象，代理内部将接口方法调用转换为 SQL 执行
- **RPC 框架**：Dubbo、gRPC 等远程调用框架中，客户端持有的本地接口实例本质是代理对象，代理内部封装了网络通信细节
- **Retrofit**：通过动态代理将 HTTP 请求接口转换为 OkHttp 调用
- **常见增强场景**：缓存、懒加载、监控统计、连接池管理等
