# 基础术语

## 什么是 Prompt

Prompt（提示词），是跟每次跟模型对话时，输入的那句话，它决定的是：这一次想要做的是什么。

这句话写得好不好，直接决定这次结果好不好。并且它是一次性的，你换个会话就得重说，经验无法沉淀，写太长还会互相干扰，但它本质上还是"这一轮的话"。

## 什么是 Skill (技能)

Skill 是把"怎么做才对"固化下来，或者说这类事是怎么做的，是一套 SOP（标准操作流程），即把一件事的最佳做法固化成一套人人可照着执行的步骤手册，是可复用的能力。

一份 Skill 本质是一个文件夹，里面包含 SKILL.md 文件，脚本、模板、参考资料。关键在于按需加载——模型发现当前任务和它相关，才把内容读进上下文，所以装几十个也不会撑爆上下文窗口。它解决的是"隐性经验没法传递"的问题：把老手脑子里的 SOP 变成可复用的文件。它决定的是「这类事该怎么做，是"方法论的沉淀"。它可以手写，也可以让 Agent 做完一件事后自己总结成技能存下来，下次直接复用。


## 什么是 MCP(Model Context Protocol）

 MCP 是一套让 Agent 连接外部系统的标准协议，它规定"模型怎么调用外部工具、外部数据怎么回传"。

 一个 MCP Server 把自己的能力（tools / resources）以标准 schema 暴露出来，模型连上后就知道有哪些工具可用、每个参数是什么。它解决的是模型凭自己做不到的事。

比如服务方提供一个 MCP Server，Agent 就能统一发现并调用它的工具、读取它的数据。它给的是能力，不是方法——比如连上邮箱就能收发邮件、连上数据库就能查表，但"怎么查、查完怎么汇报"是 Skill 和 Prompt 的事。

## Prompt 和 Skill 以及 MCP 一层层套起来

- Prompt 触发 Skill：你说"帮我处理这个 PDF"，系统匹配到 pdf 技能，把里面的规范注入进来。
- Skill 调用 MCP：技能里的步骤可能会调用外部工具，比如查行情、读表格、发邮件。
- MCP 反哺 Prompt：工具返回的数据回到上下文，成为下一轮推理的依据。
- 反过来也成立：Prompt 可以临时写一个一次性流程；Skill 里可以完全不碰 MCP，纯靠模型能力 + 本地脚本。

实用判断：一件事只做一次 → 写个好 Prompt；同样的事会反复做 → 沉淀成 Skill；需要碰外部系统/数据 → 接 MCP（通常再配一个 Skill 来规范怎么用它）。
